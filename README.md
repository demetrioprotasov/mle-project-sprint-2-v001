# Sprint 2: ML Model Improvement with MLflow

## Общее описание проекта

Проект направлен на улучшение модели машинного обучения для прогнозирования рыночной стоимости недвижимости через отслеживание экспериментов в MLflow и последовательную оптимизацию модели.

**Основная задача**: Улучшить качество предсказательной модели через систематический анализ данных, инженерию признаков и оптимизацию параметров модели.

**Бакет S3 для хранения артефактов**: `s3-student-mle-20260317-efc01cb482-freetrack`

1. **Развернуть MLflow** — установить и настроить инфраструктуру для отслеживания экспериментов
2. **Провести EDA** — провести глубокий исследовательский анализ данных

4. **Отобрать признаки** — выбрать наиболее значимые для модели

На данном этапе производится настройка серверной части: поднимается MLflow Tracking Server в связке с реляционной базой данных (PostgreSQL) в качестве backend-store и объектным хранилищем (S3) в качестве artifact-store. ### Этап 2: Проведение исследовательского анализа данных (EDA)

В ходе разведочного анализа были изучены особенности распределения признаков и целевой переменной:
Целевая переменная (price): Обнаружен сильный правосторонний скос и наличие экстремальных выбросов (медиана 11.8 млн, максимум до 975 млн).
Скрытые пропуски: Выявлены нулевые значения в признаках жилой (living_area) и кухонной (kitchen_area) площадей. Пропуски обработаны путем заполнения медианными долями от общей площади.
Корреляционный анализ: Выделены самые сильные предикторы стоимости — total_area (0.75), rooms (0.45) и ceiling_height (0.45).
Очистка: Удалены неинформативные и константные признаки (id, flat_id, studio).

---

### Этап 3: Генерация признаков и обучение модели

Для обогащения данных и подготовки их к обучению применен комплексный подход:Трансформация (ColumnTransformer): Числовые признаки отмасштабированы с помощью StandardScaler, к категориальным (building_type_int, has_elevator, is_apartment) применен OneHotEncoder.Автоматическая генерация (autofeat): С помощью AutoFeatRegressor сгенерированы новые нелинейные признаки (включая квадраты, дроби и произведения признаков, например, ceiling_height * total_area).Результат: Признаковое пространство расширилось с 15 до 45 признаков. Базовая модель CatBoost на этом наборе показала отличное качество: $R^2$ = 0.8689, RMSE = 11,571,576.

---

### Этап 4: Отбор признаков и обучение новой версии модели

Для борьбы с мультиколлинеарностью и снижения размерности применены два метода:
Фильтрация по корреляции: Удалены признаки со взаимной корреляцией Пирсона > 0.95.
Жадные алгоритмы (mlxtend): Использованы Sequential Forward Selection (SFS) и Sequential Backward Selection (SBS).
Сформировано два набора признаков:
Intersection (Пересечение): 7 самых строгих признаков.
Union (Объединение): 17 признаков (сохраняет больше нелинейных связей, выбран как основной для тюнинга).
Отбор позволил сократить размерность в два раза без существенного падения метрик, защитив модель от переобучения.

---

### Этап 5: Подбор гиперпараметров и обучение финальной модели

Оптимизация параметров проводилась на наборе Union (17 признаков) двумя различными методами для сравнения:RandomizedSearchCV:Лучшие параметры: depth: 8, learning_rate: 0.2, l2_leaf_reg: 1.CV $R^2$: 0.8692.Optuna (TPE Sampler):Лучшие параметры: depth: 6, learning_rate: 0.1445, l2_leaf_reg: 2.CV $R^2$: 0.8543 (за 10 итераций).Для финальной модели были выбраны гиперпараметры от RandomizedSearchCV с увеличением количества итераций до 1000 для достижения максимальной обобщающей способности.

### Прогресс улучшения и реестр моделей

Весь жизненный цикл проекта строго зафиксирован в MLflow. В Model Registry под системным именем feateng_model зарегистрированы 4 основные версии модели (Baseline, после Autofeat, Intersection/Union и Final Model).Для каждого запуска залогированы:Метрики: RMSE, $R^2$ (на кросс-валидации и отложенном тесте).Параметры: Гиперпараметры CatBoost и счетчики признаков.Артефакты: Графики Feature Importance, HTML-отчеты оптимизации Optuna, итоговый Scatter-plot предсказаний и объект sklearn.Pipeline (preprocessor).Воспроизводимость: Файл requirements.txt, сигнатуры данных (с примерами входов) и пути к исходному коду прикреплены к каждой версии модели.
